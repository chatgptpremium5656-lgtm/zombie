# CLAUDE.md — правила проекта Zombie

Кооп-выживание на Unity: строительство как в Rust + орды зомби (маленькие и большие, растущие волны) + колония выживших. **Не Minecraft**: никаких кубов и воксельного мира.
Платформы: **сначала macOS**, затем iOS и Android. Всё, что делается для Mac, должно уже сейчас укладываться в мобильные бюджеты.

Эти правила обязательны для каждой сессии. Если задача противоречит правилу, сначала спроси, не нарушай молча.

## 1. Арт-стиль: «чисто и просто, а не детально и криво»

1. **Стилизованный мультяшный low-poly.** Простые, читаемые формы, чуть утрированные пропорции (крупные головы и кисти, толстые стволы, округлые камни).
2. **Делай только то, что получается хорошо.** Лучше простой ассет, сделанный аккуратно, чем детальный, сделанный плохо. Если деталь не читается с игровой камеры, её не делаем.
3. **Нет мелкому шуму.** Никаких мелких царапин, трещин, заклёпок, болтов, травинок-геометрии и фото-текстур. Форма передаётся силуэтом, а не деталями.
4. **Плоское / мягкое затенение.** Цвет через вершинные цвета или одну общую палитровую текстуру (gradient/palette atlas, 256×256). Без normal map, без PBR-мешанины, без реалистичных текстур.
5. **Одна палитра на всю игру.** Палитра хранится в `Assets/Art/Palette/` и не расширяется без причины. Тёплая природа (зелёные, охра, коричневые), холодные тени, зомби в болезненных зелёно-серо-фиолетовых тонах, акценты (огонь, опасность, лут) — яркие и редкие.
6. **Читаемость прежде всего.** Игрок, зомби, ресурсы и постройки должны отличаться силуэтом и цветом с расстояния обзора камеры. Враги всегда контрастнее фона.
7. **Единый масштаб.** 1 юнит = 1 метр. Игрок ≈ 1.8 м. Строительная сетка 3×3 м (фундамент), стена 3 м.
8. **Скосы и фаски — крупные.** Вместо мелких фасок — 1–2 крупных скоса на ребро, чтобы low-poly выглядел мягко.
9. **Анимации простые и упругие** (squash & stretch, немного overshoot), без мокапа.
10. **Перед добавлением ассета** сравни его с уже существующими: тот же уровень детализации, та же палитра, тот же масштаб. Если выбивается — переделай проще.

### Бюджеты ассетов (треугольники, LOD0)
| Тип | Треугольники | LOD |
|---|---|---|
| Игрок / выживший | ≤ 3 000 | LOD1 ≤ 1 200 |
| Обычный зомби | ≤ 1 500 | LOD1 ≤ 600, LOD2 ≤ 250 |
| Большой зомби / босс | ≤ 4 000 | LOD1 ≤ 1 500 |
| Дерево | ≤ 800 | LOD1 ≤ 300, далее impostor/billboard |
| Камень / куст | ≤ 300 | LOD1 ≤ 100 |
| Строительный блок (стена, пол) | ≤ 200 | LOD1 ≤ 60 |
| Предмет в руках | ≤ 500 | — |

Текстуры: по умолчанию одна общая палитра-атлас. Отдельные текстуры не больше 512×512 и только по необходимости.

## 2. Производительность: «никаких лагов»

Цель: **60 FPS на MacBook Air M1**, позже 30–60 FPS на iPhone 12 / средний Android.

- **Рендер:** URP, Forward+, одна directional light с тенями (2 каскада), без real-time point light теней. Post-processing минимальный (tonemapping, лёгкий bloom, color grading).
- **Draw calls:** ≤ 300 на Mac, ≤ 150 на мобильных. SRP Batcher + GPU instancing для зомби, деревьев, камней. Общий материал на палитре, чтобы всё батчилось.
- **Зомби:** до 150 одновременно на Mac (мобильные — 80). Объектный пул, никаких `Instantiate/Destroy` в бою. Анимация далёких зомби — GPU/vertex animation или пониженный update rate. AI-тики распределены по кадрам (не все зомби думают в одном кадре).
- **GC:** ноль аллокаций в `Update` в боевом цикле. Никаких LINQ, `foreach` по не-массивам, конкатенации строк, `GetComponent` в горячих путях — кэшировать.
- **Физика:** простые коллайдеры (capsule/box), без MeshCollider на динамике. Слои и матрица коллизий настроены. Fixed timestep 0.02.
- **Мир:** разбит на чанки, стриминг/отключение далёких объектов, LOD Group на всех статичных объектах, occlusion по расстоянию.
- **Сеть:** серверная авторитетность (хост), синхронизация зомби пачками и с интерполяцией, не по каждому зомби каждый тик.
- **Профилируй** перед тем как сказать «оптимизировано»: Unity Profiler + Frame Debugger, цифры в описание PR.

## 3. Код: «никаких багов»

- Unity 6 LTS, C#. Пространства имён `Zombie.*`. Одна ответственность на скрипт.
- Данные — в ScriptableObject (предметы, рецепты, постройки, типы зомби, волны), а не захардкожены.
- Любая новая механика: короткий EditMode/PlayMode тест на ключевую логику (крафт, урон, волны, сохранение).
- Не ломать сохранения: версия сейв-файла и миграции.
- Перед PR: проект компилируется без ошибок и предупреждений в своём коде, сцена запускается.
- Маленькие PR, одна фича — один PR, с описанием как проверить.
